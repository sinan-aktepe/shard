# Migrating to shard 2.0

**Date:** 2026-06-13

shard 2.0 is mostly additive, but it makes **three breaking changes**. Each has a small, mechanical migration. The "zero runtime dependencies" guarantee is unchanged.

> TL;DR: most apps only touch (1) if they hand-write an `AsyncValue` `switch`, and (2) if they implement a custom `StateStorage`. (3) requires no code change — your persisted data is read as before.

---

## 1. `AsyncValue` has a new `AsyncIdle` state

`AsyncValue<T>` is now a four-case sealed union: `AsyncIdle`, `AsyncLoading`, `AsyncData`, `AsyncError`. `AsyncIdle` represents "not started" and is used by the new `CommandShard`. `FutureShard` and `StreamShard` never enter it.

**Who is affected:** only code with an *exhaustive* `switch` over an `AsyncValue` value. (`AsyncShardBuilder` users are not affected — see below.)

**Before:**

```dart
final label = switch (state) {
  AsyncLoading() => 'Loading…',
  AsyncData(:final data) => 'Got $data',
  AsyncError(:final error) => 'Error: $error',
};
```

This no longer compiles (the switch is non-exhaustive — `AsyncIdle` is unhandled).

**After — option A (add the case):**

```dart
final label = switch (state) {
  AsyncIdle() => 'Idle',
  AsyncLoading() => 'Loading…',
  AsyncData(:final data) => 'Got $data',
  AsyncError(:final error) => 'Error: $error',
};
```

**After — option B (use the new `when`, recommended):**

```dart
final label = state.when(
  idle: () => 'Idle',
  loading: (previousData) => 'Loading…',
  data: (data) => 'Got $data',
  error: (error, stackTrace, previousData) => 'Error: $error',
);
```

**`AsyncShardBuilder`:** no change required. It gained an optional `onIdle:` builder that defaults to the loading widget, so existing call sites behave exactly as before. Add `onIdle:` only if you want a distinct idle UI (typically for a `CommandShard`).

---

## 2. `StateStorage` requires a `delete` method

`StateStorage` gained `Future<void> delete(String key)` (used by the new `clearPersistence()`). Any class that `implements StateStorage` must add it.

**Before:**

```dart
class SharedPreferencesStorage implements StateStorage {
  @override
  Future<void> save(String key, String value) => _prefs.setString(key, value);

  @override
  Future<String?> load(String key) async => _prefs.getString(key);
}
```

**After:**

```dart
class SharedPreferencesStorage implements StateStorage {
  @override
  Future<void> save(String key, String value) => _prefs.setString(key, value);

  @override
  Future<String?> load(String key) async => _prefs.getString(key);

  @override
  Future<void> delete(String key) => _prefs.remove(key);
}
```

Other backends: Hive → `box.delete(key)`; SQLite → a `DELETE` statement; a file store → delete the file. The contract: after `delete`, a subsequent `load(key)` returns `null`; deleting an absent key is a no-op.

---

## 3. Persisted state now uses a version envelope

Persisted values are now written as a JSON envelope, `{"__shard_v": <version>, "__shard_p": "<your serialized payload>"}`, instead of the bare payload.

**No code change is required, and your existing data is safe:** reads are legacy-tolerant — any value written by shard 1.x (a bare payload) is treated as version 1 — so an app upgrading from 1.x loads its data exactly as before, then rewrites it in the envelope format on the next save.

**The only caveat:** a value written by 2.0 cannot be read by a 1.x build (a *downgrade*). If you ship a rollback, account for this.

### Opting into schema migration (new, optional)

If your persisted model's shape changes between releases, bump `version` and provide `migrate`:

```dart
enablePersistence(
  key: 'user',
  storage: storage,
  serializer: userSerializer,
  toPersistence: (s) => s.user,
  version: 2,
  migrate: (fromVersion, payload) {
    // payload is the raw serialized string at `fromVersion`.
    // Return it upgraded to the current `version`. You own chaining
    // (e.g. 1→2→3) when `fromVersion` is several steps behind.
    final json = jsonDecode(payload) as Map<String, dynamic>;
    json['displayName'] ??= json.remove('name');
    return jsonEncode(json);
  },
);
```

`migrate` is called **once**, with the stored version, only when the stored version is older than `version`. `PersistentShard` / `SimplePersistentShard` accept the same `version` / `migrate` parameters.

---

## Nothing else changed

Everything else in 2.0 is additive — `CommandShard`, `ComputedShard`/`computedShard`, `ShardListener`/`MultiShardListener`, `HistoryMixin`, `Shard.stream`, `StreamShard.pause/resume`, `clearPersistence`, and persistence `flushOnPause` are all new APIs that don't change existing behavior. See the `2.0.0-dev.1` section of [CHANGELOG.md](../../../CHANGELOG.md).
